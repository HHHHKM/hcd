# Implementation decisions

## D-001 · 2026-10-22 · Explicit ownership

Final-owner protection counts active direct owner memberships separately for each space and document. Inherited space roles and system administrator privileges do not substitute for an explicit document owner. Disabling an account requires another active direct owner for every resource it owns. Removing an already disabled owner does not decrement the active-owner count.

## D-002 · 2026-10-22 · Image uploads

Use @fastify/multipart 9.2.1 with bounded one-file requests. Files are content-addressed on disk, while metadata and document authorization are stored in SQLite. SVG upload supports a conservative static element/attribute allowlist, excluding active content and external references. Raw HTML isolation remains a separate incomplete feature.

## D-003 · 2026-10-22 · Verification boundary

Use pure unit tests, server rendering, Fastify request injection, type checking and production compilation for current verification. Browser localhost access was previously refused; do not attempt to bypass that restriction. Browser interaction and deployment acceptance must remain explicitly unverified until authorized and executed.

## D-004 · 2026-10-23 · HCD archive boundaries

The version-1 HCD archive adds canonical `document.json` to per-module Spec HTML, `theme.css`, image assets and the manifest. Import requires agreement between canonical JSON, module files and declared assets; the application regenerates theme styling rather than applying imported CSS. Only ordinary single-disk ZIP entries without data descriptors, encryption or ZIP64 are supported. Limits are 30 MiB compressed, 50 MiB expanded, 10 MiB per entry and 1,000 entries. Node zlib bounds actual inflation; CRC32 and asset SHA-256 validate bytes. Raw assets and arbitrary website ZIPs remain unsupported.

Staged files are stored by content hash and bound to a document only in the confirmation transaction. Failed/discarded imports can leave unreferenced content-addressed files; a later garbage-collection and retention task must remove those safely. Request limits and two concurrent archive imports bound current service load; multi-process shared limiting remains future work.

## D-005 · 2026-10-23 · Static raw rendering and authorization

Static raw assets now use sanitized HTML and a separate render hostname. Five-minute HMAC URLs additionally bind a user or share-link context so serving can recheck disabled users, membership, current/pinned publication and revoked links. This extends the basic signature payload in the reference design. Main-origin asset routes only return images; raw URLs are issued separately. Script-enabled raw blocks are explicitly rejected for now. Exports include sandboxed raw content with an embedded CSP. The local development hostname is render.localhost; production requires a distinct HTTPS hostname. Browser-level isolation tests remain unexecuted under the existing browser restriction.

This supersedes the raw-asset limitation in D-004 for static HTML assets; arbitrary website ZIP import is still unsupported.

## D-006 · 2026-10-23 · Email outbox

A SQLite notification insert trigger writes an outbox row in the originating transaction. Existing notifications are not backfilled. Per-event preferences and current document membership are rechecked at delivery. Claims have renewable leases and random ownership tokens; six failed attempts terminate delivery. Delivery is at-least-once across crashes after SMTP acceptance and before the sent marker. The worker stores safe error codes, not SMTP exception text. Real SMTP is disabled unless host and sender are explicitly configured. Tests use injected delivery and a local fake SMTP server. Account/visitor email workflows and daily summaries are separate remaining features.

## D-007 · 2026-10-23 · Account mail and guest identity

Security mail joins the existing durable outbox but stores tokens/codes in AES-256-GCM ciphertext using a separate HKDF-derived key. Associated data binds the record ID, purpose, source credential and recipient. Eligibility is rechecked before decryption; terminal delivery and ciphertext removal share a transaction. Credential mail is prioritized over ordinary notification backlogs. Public forgot-password responses use 204 uniformly; request limiting is currently single-process. A reset also revokes existing PATs and sessions.

Guests remain separate from workspace users. SQLite migrations permit nullable member authors plus a guest foreign key on comments and AI tasks, preserving existing records. Codes use a keyed digest and are bound to challenge/link/email/name. Failure counters persist by normalized email across links, resends and process restarts, with a five-attempt hourly lockout. Sessions are bound to one link and expire after seven days. Render authorization binds the guest session record and rechecks the live link; signed render URLs are still transferable bearer capabilities until expiry or revocation. No external guest email or token is exposed in public comment responses.

## D-008 · 2026-10-23 · Daily summaries

Use the existing SMTP worker and a durable user/local-date deduplication record. Schedule at or after a configured local hour, defaulting to 09:00 UTC. Gather currently pending submissions from documents the recipient can review, combining them into one bilingual email without submission bodies. Recheck access, opt-out and pending status during delivery and cancel mail older than one day. No historical backfill is performed. The current permission model requires document/space ownership (or administrator authority) for review. Timezone/DST and restart behavior are covered by integration tests.


## D-009 · 2026-10-23 · Space notifications and credential cleanup

Feishu/Lark integrations have encrypted per-space/per-kind configuration revisions and an independent transactional delivery queue. A configuration change cancels older pending jobs; workers recheck revision, recipient email/access, source status and lease ownership before each network request. Already dispatched requests cannot be recalled. Cards use plain text for user content. Only the two official origins are accepted in production. Fixture origins are constructor-only test dependencies, never user settings or environment defaults.

Webhook signing follows the [official custom bot documentation](https://open.feishu.cn/document/ukTMukTMukTM/ucTM5YjL3ETO24yNxkjN.md): HMAC-SHA256 with the timestamp/newline/secret as key and an empty payload. App delivery uses [email-to-user lookup](https://open.feishu.cn/document/server-docs/contact-v3/user/batch_get_id.md) and [interactive messages](https://open.feishu.cn/document/server-docs/im-v1/message/create.md). Feishu uses the new [client-credentials token endpoint](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token.md). Lark currently uses the legacy tenant-access-token route; its real tenant compatibility remains unverified. Sending and lookup permissions are `im:message:send_as_bot` and `contact:user.id:readonly`.

Application UUIDs are stable per queued delivery, with the documented one-hour upstream deduplication window. Webhooks and crash recovery remain at-least-once. All tests run against local fixtures/injected transports and do not message real users or groups.

Minute-based maintenance performs only credential expiry cleanup. Active lockouts, cooldowns and processing leases are preserved, while unusable encrypted mail secrets are erased. Source documents and audit metadata are retained. Asset garbage collection and configurable audit retention remain separate work.


## D-010 · 2026-10-23 · Frozen export jobs and isolated PDF service

Freeze the authorized published snapshot, or the preview's clean pending candidate, in the export creation transaction. Exclude a whole conflicting submission, expose excluded IDs, and reject pending inclusion against a historical version to avoid ambiguous merge bases. Pending visibility follows the reference role matrix (commenter/editor/owner), not owner-only review authority. PAT requests additionally require read scope, enabled document AI access and live document scope.

Durable SQLite jobs serialize work with renewable leases. Each claim writes a distinct private temporary file and atomically renames it; only the owning claim can record completion. Interruptions can repeat rendering but cannot overwrite a newer worker's file. Completed snapshots are erased; results expire after 24 hours and abandoned files after one day. Job quotas are checked in the same transaction as insertion. POST requests are independent jobs, not idempotently deduplicated.

Signed render-domain downloads use kind `x`, attachment disposition and live creator/access/PAT checks. As with other render URLs, the signature is a transferable temporary capability. PDF HTTP requests disallow redirects, have a 60-second abort signal and validate content type, PDF markers and a 50 MiB output limit. An independent exporter service uses the installed Playwright 1.64.1 API, disables JavaScript and network requests, and requests A4 print output. Its Docker image tag matches that exact dependency. No browser or container was launched: tests use injected renderer functions and synthetic PDF bytes. Real PDF fidelity, container startup and network isolation remain unverified under the existing browser constraint.


## D-011 · 2026-10-23 · Public-client OAuth and resource binding

Follow the current [MCP authorization guidance](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) and [client-registration guidance](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration). Support the recommended HTTPS Client ID Metadata Documents and retain dynamic registration for compatible clients. Public clients use code + PKCE S256; confidential authentication methods are rejected. Metadata fetching pins a verified public IPv4 address, retains hostname TLS verification, rejects redirects and bounds payload, DNS/request time and cache lifetime. IPv6-only metadata URLs are an explicit current limitation.

Consent is explicit, browser-secret bound, account bound after inspection, and restricted to selected AI-enabled readable documents. No future documents are implicitly added. Grants have absolute chosen lifetimes up to 30 days, access tokens up to one hour, and rotated refreshes cannot extend the grant. Reuse detection revokes the family in a committed transaction: return an error value, never throw inside the revoking transaction. Only PAT and oauth_access kinds authenticate API calls; oauth_refresh is solely an exchange credential. Validate issuer/resource against configured APP_URL, not request Host. Scope narrowing applies to newly minted access tokens.

User settings list one record per OAuth family. Reset/disable/revoke invalidate the family and all outstanding access, refresh and code credentials. Document role and AI access are checked on token-backed document requests, including signed asset reads. Token document reads no longer expose private drafts, and token submissions preserve those drafts. Read-only submission/preview access now separates role visibility from write scope.

Browser/real connector acceptance is still not executed. The existing MCP HTTP protocol subset remains 2025-03-26 independently of the OAuth authorization guidance version. No broader protocol compliance is inferred from passing OAuth tests.

## D-012 · 2026-10-23 · SDK stdio bridge and local module identity

The [official SDK](https://github.com/modelcontextprotocol/typescript-sdk) now publishes its stable implementation as `@modelcontextprotocol/client` and `@modelcontextprotocol/server`. Use 2.3.1 for the CLI bridge, with a low-level Server forwarding to a Client. Preserve the existing HTTP protocol revision explicitly. Publish only tools/resources actually supported by the upstream. Per-call cancellation reaches the SDK request; the current stateless backend does not provide cancellable server jobs. Progress, sampling, subscriptions and elicitation are not advertised.

Pin every SDK HTTP request to the configured endpoint, reject redirects, omit cookies and bound network time. Keep stdout exclusively for JSON-RPC, sanitize transport exceptions, recheck upstream credentials for every list/read/call, and close on EOF/signals. Tests use real SDK HTTP connections and a subprocess over stdio with local fixtures, not browser automation. The server HTTP dispatcher still needs migration/full protocol coverage; the bridge does not complete AT-30 by itself.

CLI module filenames determine order, while IDs determine identity. Renames no longer appear as deletions, reorder-only edits are submittable, and new nodes receive IDs. Duplicate IDs fail explicitly. `diff` uses core structural operations. Pull refuses uninitialized nonempty destinations, checks server snapshots before changing files, protects edits/renames/reorders, and cleans stale module files after a valid refresh. Forced refresh replaces module HTML in an initialized checkout and retains unrelated files. Browser authorization, local rendered previews, durable submission retry receipts and full temporary-ID reconciliation remain unfinished.

## D-013 · 2026-10-23 · AI task attempts and suggestion freshness

Bind every claim to the exact access-token record and a random 128-bit claim ID. Require both for task submissions, failure and completion, fencing late workers even when the same user/token reclaims. Freeze the official base version at claim; keep ordinary review merging for later human changes. Three attempts bound both explicit failures and timeouts. A minute maintenance sweep and worker-entry checks reclaim expired leases. Expiry runs outside rejected worker transactions so an error cannot undo recovery. Preserve per-attempt token/user IDs, timestamps, outcomes and successful submission links. Tokens themselves are never stored in task records or returned through task APIs.

This extends the reference task API with required claimId, and bounds timeout retries like explicit failures. OAuth rotation creates a different token identity and does not transfer active claims. A task may return to the queue after expiry; new work must read the newly returned baseline. Requests from API tokens remain requested even if the token owner is a document editor/owner; human approval cannot be obtained through a token.

Resolve tasks bind a server-generated SHA-256 fingerprint of preview/document IDs, base version, ordered submissions, revision, existing resolutions and conflict content. All preview changes invalidate old suggestions. A new attempt clears earlier provisional results. Suggestions must validate against a complete candidate even when other conflicts remain unresolved, avoiding validation that would otherwise omit a whole conflicting submission. Human adoption is transactional, rechecks the fingerprint and records aiTaskId as provenance. Restrict structural advice to an allowed current/incoming choice; free-form values use only existing manual-resolution paths. No worker route can publish or apply a suggestion.

Readonly preview computation has no saved preview ID and does not write/stale saved reviews. Saved-preview reads derive staleness without modifying database state. UI interactions, real AI connector runs and browser acceptance remain unverified.


## D-014 · 2026-10-23 · Submission inputs, conservative identity review and CLI receipts

Accept exactly one of full content, strict operations or module HTML. Hash the validated original request before assigning random IDs; normalize an omitted message to the empty string and exclude the idempotency key from that hash. Generate content/operations/ID maps and insert the submission in one SQLite transaction. Retries return the persisted first result. Retain the former normalized-content hash path for pre-migration full-JSON submissions. Input failures roll back all changes and notifications. Task operations additionally check each touched module so an out-of-scope change followed by a reversal cannot pass only a final-snapshot check.

Module replacement uses the immutable requested base, explicit deletion and stable shared-anchor insertion order. Reject duplicate IDs, foreign existing node IDs, invalid wrappers and lossy parser warnings; cross-module moves use operations. Similarity reconciliation preserves explicit IDs globally and matches missing/unknown IDs only among same-kind siblings. Use the reference 0.3/0.6 thresholds and additionally mark near ties uncertain. Bound tree depth/nodes, candidate comparisons and edit-distance work; do not silently downgrade an exhausted budget into new identities. Bound ambiguity detection to a sorted pass instead of repeated all-pairs scanning.

The current snapshot-based merge is retained. An uncertain identity creates a whole-submission owner confirmation gate, blocks publication and excludes the entire submission from pending exports. AI cannot resolve this gate. This is an explicitly partial product behavior: per-operation accept/drop, dependent-operation handling and the full specification merge algorithm remain unfinished. uncertainCount currently counts uncertain recovered identities, not operations. The UI can open the submitted document over the review overlay; browser behavior is still unverified.

CLI receipts freeze the exact payload, target and key before HTTP I/O, then atomically replace the private JSON ledger. Unknown outcomes retain pending requests; changed source files cannot replace them, while explicit --retry replays the saved body. Preserve legacy receipts when upgrading. Use a dedicated SQLite BEGIN IMMEDIATE lock held across the read/network/write cycle. Never delete the lock database: PID-file stale recovery has a check/delete race and can permit concurrent writers. A real child-process SIGKILL test verifies lock release and exact request/key recovery. Receipt cancellation and handling persistently rejected pending requests remain unfinished; do not silently discard uncertain outcomes.

Tests use Fastify injection, local SDK HTTP/stdio and local subprocesses. No browser, real external messaging, PDF renderer or deployment acceptance was performed.


## D-015 · 2026-10-23 · Operation-aware review and resolution context

Operation/module-HTML submissions now replay their stored permanent-ID operations over the current candidate, ordered by creation time then submission ID. Keep legacy full-JSON merging for compatibility while its ID-preserving conversion remains unfinished. One unresolved operation excludes the entire submission, including its inserted-ID bookkeeping, from later submissions and exports. Successful earlier operations within the same submission provide the state for later operations. Do not speculate an unresolved operation's outcome. Explicitly track dropped/blocked insertions and their target, parent, anchor and cell/category-reference dependencies.

Uncertain matches now create one accept/drop decision per operation. Acceptance can expose a second conflict at the :2 suffix; a whole-submission identity gate is no longer used for stored operations. Return operation outcomes, including dropped dependencies. Restore missing original blocks from the immutable base; preserve surviving containers and restore only missing paths within them. When the original module is gone, generate a deterministic Restored module. Refuse restoration when existing moved descendants would duplicate IDs. A missing block restoration includes the original block subtree; it is not a reconstruction of only the changed text.

Bind resolutions to the operation, conflict values, target position/subtree hash and destination list. Restoration and invalid combined structures also bind the working snapshot. Re-evaluate every time; obsolete decisions become unresolved and are removed from saved resolutions. AI suggestions retain their stricter preview/revision/claim binding and cannot accept identities or select structural placement. Validate manual values immediately, final document structure after the submission, and return an explicit whole-submission drop conflict for invalid combinations. Intermediate incomplete containers remain possible within one valid operation transaction.

Validate document references before canonicalization in both strict application and merge. The old per-operation normalization could discard cells/categories whose references had not yet been inserted or had been concurrently deleted. Preserve them until final validation: future references established later in the same request survive; unresolved references fail explicitly. Coupled deletions still intentionally remove affected cells/values.

Persist preview items and expose candidate hashes. Publishing recomputes the saved decisions and compares the candidate inside the publication transaction. Adding preview items invalidates pre-upgrade open merge previews once, since old identity decisions and candidate semantics must not be reused. The migration preserves published versions and saved data; normal subsequent restarts do not invalidate current reviews.

This does not complete the full BUILD_SPEC merge/editor acceptance: full-JSON client migration, complete change presentation, all fixture/property cases and real browser behavior remain pending. Tests exercise core algorithms, Fastify APIs, actual SQLite reopen/upgrade, exports and direct publication; no browser or deployment was run.


## D-016 · 2026-10-23 · ID-preserving JSON conversion and legacy review migration

All submission formats now use operation merging. Complete JSON remains the web/CLI wire format, with permanent IDs preserved at the compatibility boundary. Validate the snapshot before canonicalization, derive temporary operations, resolve each temporary ID back to its supplied permanent ID, strictly replay, and require exact canonical equality. Reject missing/duplicate IDs and invalid references; do not normalize them away. Unsupported node-kind/theme-reference/raw-asset changes fail explicitly, as do diffs over 500 operations. Unchanged JSON snapshots remain accepted for compatibility.

Expose the temporary identity to IdSource.next as an optional second argument so conversion uses an explicit mapping instead of relying on allocator call order. Ordinary operation/HTML requests still allocate new permanent IDs and enforce temporary IDs for inserted nodes. JSON responses keep an empty idMap because their identities are already permanent; newly created records now return an operation count.

Fix diff insertion to preserve cells and chart values referencing existing columns/categories. Stage complete operation sequences without final-schema checks on intermediate containers; final strict replay remains mandatory before accepting a submission. Compute each deletion hash after preceding deletions. Pure removed subtrees are deleted before insertions, while removed containers with surviving descendants wait for those descendants to move. This intentionally refines the reference's generic deletion-last ordering: coupled hashes must not contain IDs that only the later allocator knows. Move-associated cell/value updates are scheduled according to the source and destination containers. Use an O(n log n) longest-increasing-subsequence calculation for unique-ID list ordering instead of a quadratic LCS matrix.

Legacy content-only pending submissions are converted read-only at preview time against their immutable baseline. Preserve content, request/payload hashes, generated ID maps and old receipts byte-for-byte; do not eagerly rewrite historical records. An incompatible legacy snapshot produces an explicit invalid-structure conflict with a discard choice, is excluded from pending exports, and remains available to inspect or withdraw. Remove the old snapshot merger to avoid two merge semantics. A schema_migrations marker invalidates existing open merge previews exactly once, without touching restore previews or published versions.

Request replay still checks existing receipts before conversion, including the older normalized-payload hash fallback. The CLI frozen-payload ledger and lock are unchanged. Invalid AI manual values retain the established INVALID_SUGGESTION API code despite stricter operation validation. Browser/IME/deployment acceptance, complete diff/change presentation and native client operation generation remain separate unfinished work.


## D-017 · 2026-10-23 · Immutable review display and original proposals

Presentation is derived data, separate from canonical versions and receipt payloads. Replay stored permanent-ID operations in their exact order, preserving opIndex and taking module, position and node snapshots at each operation. Require final replay equality before returning a comparison. Legacy content-only submissions convert read-only; failures return an explicit unavailable reason. Preserve existing API changes fields and add changeSet. Historical net comparison may exceed 500 rows without relaxing the submission operation limit.

Store presentation with each new preview/revision, including its immutable current-version baseline, actual candidate net changes, and original submissions against their individual baselines. GET never recomputes it from a newer document version. Existing previews gain a nullable column, without another invalidation; null means display unavailable. Restore captures the current-to-historical comparison. Per-operation evaluation outcomes are not contribution attribution: unresolved work rolls back as a whole, manual resolution can differ from a proposal, and later submissions can overwrite earlier results. Mark whole-submission exclusion explicitly. Only original proposal rows carry sources; do not invent provenance for the net candidate.

Text display preserves whitespace, line breaks, marks and link destinations without canonicalizing fragments. Bound Myers work to 200,000 steps and fall back to explicit replacement. Bound each ChangeSet to 8 MiB and combined review display to 16 MiB, prioritizing candidate detail; oversized or failed comparison is never reported as no changes. Paginate web rows and lazily load review/submission views. CLI human output escapes terminal controls, while --json and --ops produce standalone machine-readable JSON. Browser visual/interaction acceptance is still pending.


## D-018 · 2026-10-23 · Local previews, author-bound cancellation and inert chart data

This supersedes the unfinished local-preview and receipt-cancellation statements in D-012 and D-014 without rewriting those historical records. Native CLI operation submission, complete local reconciliation and browser authorization remain unfinished.

Render the local working copy into `.mdoc/preview.html`, with an explicit unreviewed-content/base-version banner. Asset-free documents render offline; referenced images/raw content require credentials and are fetched again on every run to recheck access. Keep content-hash files under `.mdoc/assets`, but never reuse that cache to bypass a failed current read. Reject redirects, verify image content, sanitize raw HTML and send no PAT to signed raw URLs. Limit unique assets to 100, each asset to 10 MiB, aggregate asset data to 40 MiB and estimated inline expansion to 64 MiB, counting repeated references. Replace the preview atomically only after complete success; a failed run may leave hash assets but preserves the prior preview. The preview contains document content, not authentication credentials. Only `mdoc preview --no-open` has executable acceptance; operating-system opening and browser visual behavior remain unverified.

Receipt inspection is read-only and excludes the frozen document payload from summaries. Cancellation retains the SQLite process lock and original payload/key throughout recovery. Save `cancelling` before network mutations, recover the exact original request when its submission ID is unknown, then read and withdraw that same pending submission. Recovery can create the original request before withdrawing it. A lost withdrawal response can be settled only by a verified read. Never treat 403/404, validation failure or absence of a response as proof that nothing was accepted. Unresolved cancellation blocks submit/retry; explicit cancel resumes it. Confirmed withdrawal becomes `cancelled` without deleting the request, and an identical fingerprint cannot be resent automatically. Published/rejected submissions retain `submitted` with their observed server status; cancellation cannot reverse publication. Permanent recovery rejection remains an unresolved operational case.

Server idempotency is scoped by document, author and key. Therefore read `/me` with the selected credential and persist `authorId` before the first POST. Keep that credential fixed through each operation; reject a different account before replay or receipt changes. Verify document, submission and author identity on replies. Read older receipt formats without altering frozen payloads or keys. An old unknown-outcome receipt without author binding and without a submission ID cannot be safely replayed and is blocked. An old known submission ID may be read to prove the author before binding and cancellation. Normal submit cannot blindly reuse an old unbound completed receipt. Preserve the legacy receipt list; do not infer identity from whoever is currently logged in. Unit and child-process tests cover cancellation intent durability, lock exclusion, SIGKILL recovery, lost responses, published races and account switching.

Accept the Spec HTML chart serializer’s inert `application/hcd+json` data block through the module-submission boundary. A chart figure must occupy a valid direct module/column/card position and have exactly one non-whitespace child: a script with only the required inert type attribute. Validate known payload fields, bounded strings/arrays, finite-or-null values and matching series/category counts before parsing into canonical data. Do not generalize this exception to executable scripts, event attributes, extra script attributes or misplaced chart payloads. Strict operations and ordinary human review remain unchanged.

## D-020 · 2026-10-23 · Device-code CLI authorization and revoking logout

This supersedes the unfinished CLI browser-authorization implementation status in D-019 and earlier decisions. Device authorization, the consent page and CLI transport are implemented. Their executable verification is limited to local HTTP/API, SSR and unit tests; real browser consent interaction, automatic opening, visual acceptance and deployed-server acceptance remain unverified.

Create a ten-minute request using a random eight-character display code and an independent 256-bit poll secret. Return the configured APP_URL origin's `/cli-auth?code=XXXX-XXXX` URL, never a caller-selected host or a URL containing the poll secret. Anonymous start/poll requests reject unexpected browser origins; request rates, active request count, payload size and the three-second polling interval are bounded. The display code only identifies a request. First authenticated inspection binds it durably to the inspecting user and exact live session. Approval requires that binding, the normal write guard and a fresh session/account check inside the transaction. PAT/OAuth identities cannot approve, and switching accounts or sessions cannot reuse the inspection.

Request `read`, `comment`, `submit` and `ai_tasks` by default, with `preview` as an explicit option. Approvers may narrow scopes, select currently accessible documents or explicitly choose all current/future documents they can access, and choose 1–90 days with a 30-day default. The page defaults to specific documents with an empty selection and requires confirmation of the displayed code and computer. Issue an ordinary PAT so existing live role, scope, document-list, AI-access and owner-action restrictions remain authoritative. As with personal-token settings, document selection records membership scope; an AI-disabled document remains inaccessible through the resulting token.

Approval creates exactly one PAT in the same transaction as the terminal decision. Repeated approval returns its status without changing the first scopes, document selection, lifetime or token. Store only keyed digests of the poll secret and bearer. Derive the bearer deterministically with a separate HMAC domain from the server secret and disposable request identity inputs, allowing the same `pollToken` to retrieve the same PAT after a lost response within the original ten-minute window. Every delivery rechecks the approving session, active account, saved token hash/revocation/expiry and selected-document membership. Invalid delivery becomes denied and cannot mint a replacement. Expiry erases the poll-hash derivation input and session binding; an issued PAT keeps its separately chosen lifetime. This repeatable, bounded delivery deliberately replaces the reference's one-response-only token delivery, which could strand a valid token after a lost poll response. It does not create an OAuth grant or refresh credential.

`mdoc login <server>` prints the verification URL/code and requests operating-system browser opening. `--no-open` leaves opening to the user. An explicit `--token` or `HCD_TOKEN` preserves existing-PAT login; `--token` takes precedence, and `/me` verifies either login result before persistence. The MCP bridge can also use `HCD_TOKEN` directly with `--server`. These paths retain same-origin destination validation, redirect rejection, bounded responses, cancellation and timeouts. A denied, expired, cancelled or failed login does not replace an existing credential.

Store per-origin records in the existing credentials JSON location, with private files and atomic synced-temp-file replacement. A SQLite process lock serializes updates and is released by process exit. Reject corrupt/duplicate records and symlinked paths instead of resetting the file. Keep other servers' credentials and delete only the exact revoked token, so a concurrent login replacement survives logout. Unix mode `600` applies to credential/lock files; newly created credential directories use `700`. This is plaintext local bearer storage protected by file permissions, not an OS keychain or encrypted credential vault.

Default `mdoc logout [server]` calls the bearer-self-only revoke endpoint before removing the selected local record; no arbitrary target ID is accepted. PAT revocation affects that token, while OAuth access-token revocation invalidates its family. A `401` allows removal of an already unusable credential. Preserve credentials on network failure, `403`, `5xx` and an older server's `404`; never interpret a missing revoke endpoint as success. `--local-only` explicitly removes local saved records without revoking server access. Environment-only tokens are not selected.
